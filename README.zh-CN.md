# ScaleNative

ScaleNative 是一个 AI 加速器处理单元（PE）的研究原型，内容包括 RTL、仿真测试、一套开源
版图流程的配置文件，以及一篇论文的草稿。这个 PE 由一个小的控制核带一个矩阵单元
（Tensor 单元，做 GEMM 的脉动阵列）和一个向量单元（Vector 单元）。研究的问题是：矩阵单元
把结果交给向量单元时，不先转成标量浮点，而是以块缩放数据（一组尾数共用一个缩放因子）的
形式交过去，会带来什么，在什么条件下值得这样做。项目名的意思是结果在这次交接中保持原本的
块缩放形式。

本项目还在进行中。论文是草稿，占位很多；RTL 只实现了论文所述设计的一部分；这次首次公开
发布的内容，还没有在你现在看到的目录结构下实际跑过。使用本仓任何内容之前，请先读
[状态](#状态)与[已知限制](#已知限制)两节。

> **`v0.2.0` 这一版的 MX 状态**
>
> 本设计覆盖 OCP Microscaling（MX）格式的一个子集：元素为 E4M3 的 MXFP8、MXFP4 与
> MXINT8，块缩放因子为 E8M0。它不是完整的 MX 实现，我们也不称之为支持 MX。
>
> - **已做，只在单个乘加单元上核过：** 操作数为 MXFP8（E4M3）、MXFP4 与 MXINT8、块缩放
>   因子为 E8M0 的乘加。阵列按沿 K 方向每 32 个元素一块来设计。
> - **在 Vector 单元里已做，有单元级测试：** MXFP4 与 MXFP8 的紧凑存储。它每 16 个元素写
>   一个 E8M0 缩放因子，所以不是 OCP MX 的块 32 容器。
> - **还没做：** 带 MX 操作数的阵列级 GEMM（没有仿真过）；K 大于 32 时的缩放因子装载；把
>   GEMM 结果送进 MX 存储的通路；MXFP6（在计划中）。
> - **不做：** 元素为 E5M2 的 FP8。
> - **交接的块：** Tensor 单元交给 Vector 单元的块用内部格式，是 NVFP4 式块 16 粒度（16 个
>   尾数共用一个 2 的幂指数）。我们不称之为支持 NVFP4。
>
> 细节见[已知限制](#已知限制)第 15 至 17 条。

## 状态

`v0.2.0` 是首次公开发布，供合作者与读论文草稿的人阅读，不是一份完成的制品。

**这一版 RTL 实现了什么**

- 一个 PE 顶层（`pe_top`）：Ibex RV32IMC 控制核（取自 lowRISC 的源码）、2 KiB 指令存储
  与 4 KiB 数据存储、一个带四个上下文的命令处理器（从环形队列取 32 字节的描述符并派发）、
  一个 DMA 引擎，对外是 32 位的流入、流出口。
- Tensor 单元：16 x 16 的输出驻留式脉动乘加阵列。每个单元由 4 位乘 4 位的乘法器拼成，
  每拍接受一组 BF16、MXINT8、两个 FP8（E4M3）或四个 FP4 操作数，带一个宽的浮点累加器。
  在阵列出口，每行 16 个结果组成一个块：16 个 16 位尾数加一个共享指数，另带元数据。
- 交接通路：一个小的 valid/ready FIFO 把这些块从 Tensor 单元送到 Vector 单元。Vector
  单元在入口核对每个块的块大小、缩放格式与 epoch。
- Vector 单元：一个核，16 条通道，每条是 16 位有符号尾数，整块共用一个指数。在 PE 一级
  从头到尾接通的通路是：从交接通路取一个 GEMM 结果，加上从本地存储读出的第二个操作数
  （残差加），再把和写回本地存储。在 PE 一级，这条通路测过握手，还没有测过数值。Vector 的
  RTL 里还有别的功能并有单元级测试，例如 MXFP4 与 MXFP8 的紧凑存储、归约单元，但不是都能
  从 PE 顶层用到（见已知限制）。
- 32 KiB 的本地存储（L2），由 Tensor 单元、Vector 单元与 DMA 引擎共用。

**论文写的是目标设计，不是这一版 RTL**

论文与其中的架构图按我们要做成的设计来写。目标设计里还没有定、或还没有数据的地方，论文里
是占位。下表右栏列的是目标与规划点，这一版都没有实现，栏里的数也都不是测得的结果。

| 方面 | 这一版 RTL | 论文中的目标设计（未实现） |
|---|---|---|
| Vector 核 | 一个 Vector 单元，16 条通道 | 每个 PE 两个 Vector 核。Tensor 单元的两个排空口各接一个核。屏蔽一个核之后 PE 仍具备全部功能。候选形态还剩两种：流水核加通用核，或两份相同的核 |
| Vector 的运算 | 打包与拆包、拆分与合并、残差加、重标定、块内归约。没有 exp、没有通用乘法、没有选前 k | 补上负载需要的运算。索引分数的后处理与选前 k 放进 Vector 核，不放在交接通路的入口。放在两个核里的哪一个还没有定 |
| Tensor 的吞吐 | 操作数为 FP4、FP8、BF16 时每拍 1024、512、256 次乘加（MXINT8 也是 256） | 规划点：4 bit 与 8 bit 两档做大到每拍 2048 与 1024 次。BF16 档仍是 256 |
| 每个 tile 的固定开销 | tile 控制器在乘加步之外每个 tile 固定花 56 拍，另外还有操作数重载 | 规划点：5 拍。等综合结果出来再看要不要调整 |
| Tensor 的操作数 | 每条命令都重新装载全部操作数 | 一个操作数驻留并双缓冲。另一个从本地存储流入 |
| 本地存储（L2） | 32 KiB | 以每 PE 128 KiB 为起点 |
| 控制核的存储 | 指令 2 KiB、数据 4 KiB | 4 KiB 与 8 KiB |
| PE 的对外接口 | 32 位流口，另有独立的启动口。没有网络接口 | 片上网络端点。规划点：本地口的有效载荷每拍 64 字节。启动经由网络。设计在定 |
| 一个 PE 之外 | 没有。没有多 PE 的 RTL | 多个 PE 组成的二维 Mesh，边上有共享存储（L3）。L3 的规划范围：一张 8 x 8 Mesh 配 128 至 256 MiB。设计在定。论文里系统级的结果由建模给出 |
| PE 的型别 | 一种 PE 设计 | 同构的 PE，并为第二种型留口子：PE 的空闲上报与任务描述符里留能力位，第二个 Vector 核做成生成期参数 |
| 错误 | 执行期错误到不了命令处理器 | 错误汇集到命令处理器。交接失败以可见的错误结束 |
| 结果的身份与发布 | 块不带任务身份。没有对象表、读者租约与发布这一步 | 块带上下文、标签与行号。结果经对象表发布或中止 |
| 块结果的存储 | 只存尾数（MXFP4 与 MXFP8 的紧凑存储除外） | 尾数加一条带元数据的指数旁路记录，存下的结果可以读回再消费 |
| 数值格式 | 上面列出的单元级模式。MX 只在单元级核过 | 加 MXFP6，阵列级的 MX（含 K > 32 时的缩放因子装载），GEMM 结果的 MX 存储 |
| 注意力的精度与内核 | 没有专门的安排。一个 tile 的两个操作数只有一种格式 | 把注意力核心的 Q 量化到 8 bit，使核心走 8 bit 档。在线 softmax 与选前 k 的做法可以与参考软件内核不同，每一处不同都会在论文里写明。它们对模型质量的影响本项目不评 |
| 稀疏 | 稀疏描述符会被接受，但没有实现 | N:M 稀疏作为可选的一层，只限验证过的部分 |
| 交接方式 | 只有块缩放的直接交接 | 比较几种交接方式：块表示或标量表示，直接交接或经本地存储，以及在生产端融合 |

**MX 格式**

以本页开头的 MX 状态框为准。这一版覆盖的内容，我们称为 OCP MX 格式的一个子集，不称为
支持 MX：三种格式只在单个乘加单元上核过，Vector 单元的紧凑存储也不是 OCP MX 的块 32

块是内部格式，属 NVFP4 式块 16 粒度，我们不称之为支持 NVFP4。

### RTL：功能

7. **Vector 的错误到不了命令处理器。** `pe_top` 没有接 Vector 单元的错误输出，所以一条以
   错误结束的 Vector 命令会被报成已完成。操作数超时、操作数到达顺序不对、块大小不匹配，
   都会给出错误的数据而没有任何报错。
8. **在 PE 一级，只有一条 Vector 命令能用在 GEMM 结果上。** 就是第二个操作数在本地存储里
   的残差加。两个操作数都来自交接通路的残差加等不到第二个操作数，因为 Tensor 单元
   把每个块都标成第一个操作数。装载、激活与普通存储这三条命令按块大小 32 设置，而 Tensor
   单元给出的块大小是 16，所以这些命令执行期间从 Tensor 单元到达的块会被判为不匹配。由于
   第 7 条，这些情形最后都显示为「已完成」。
9. **没有实现的稀疏模式会被接受。** 选择 2:4 或 1:4 稀疏的描述符（BF16 或 MXINT8，输出
   驻留）会被接受并执行，但逐单元的选择通路并不存在。结果是错的，也不报错。请不要使用稀疏
   模式。
10. **交接处的不匹配不会按原样报出。** 一个块与 Vector 单元的预期不符时，流水线停住，约
    1023 拍后这条命令以操作数超时的错误码结束。
11. **块不带任务身份。** 块离开 Tensor 单元时，上下文与标签两个字段固定为 0，Vector 单元
    也不核对它们。同一个 epoch 里有两条以上的生产流时，消费方可能取走别的流的块。这一点
    没有仿真过。
12. **含特殊值的行会被丢掉。** 一行结果里有 NaN 或无穷，或者无法用一个共享指数表示时，
    这一行在交接 FIFO 的入口被丢弃，而不是以错误结束。少了这一行对消费方的影响还没有
    刻画过。
13. **交接通路上的时钟门控与软复位。** Tensor 的时钟在其输出有效时被关掉的话，一直有时钟
    的 FIFO 可能反复收下同一个块。Vector 的时钟被关掉期间发出的软复位，Vector 单元看不到。
    这两条都是读 RTL 得出的，没有在仿真里复现。另有一条只在网表里存在的软复位风险，见
    第 32 条。
14. **本地存储在仿真里与在 ASAP7 网表里行为不同。** 仿真里，存储封装是带字节掩码的真双口
    存储。ASAP7 分支把它映射到单口宏上：写优先于 A 口的读，A 口的读优先于 B 口的读，两个
    口共用一路输出，字节掩码被忽略。没抢到的那次读仍然给出有效标志，读到的是旧数据或另一个
    地址的数据。L2 的仲裁器里没有任何机制阻止同一拍里对同一个 bank 发生这样的两次访问。
15. **MX 只在单元级验证过。** 带 MX 操作数的 GEMM 没有在阵列级仿真过。tile 描述符里没有
    缩放格式字段，所以阵列总是按 E8M0 处理缩放因子；缩放因子的装载预计只在 K 不超过 32 时
    正确。没有把 GEMM 结果送进 MX 存储的通路。
16. **紧凑存储不是 OCP MX 的块 32 容器。** 它每 16 个元素写一个 E8M0 缩放因子，选了块
    大小 32 时也是这样。按「每 32 个元素一个缩放因子」推算存储量的说法对它不成立。
17. **Vector 存储里的静默回退。** 存 MXINT8 数据，或者缩放因子不是 2 的幂的紧凑存储，
    实际写下的是完整的 256 位内部载荷，不写缩放因子旁路记录，也不置错误标志。
18. **存下的块结果不能连同缩放因子读回。** 普通存储只写尾数。PE 内部也没有把存下的结果
    送进下一次 GEMM 的通路：能用的只有输出驻留模式，也没有转置这一步。第二次消费只存在于
    Vector 单元内部（即第 8 条里的残差加）。Vector 单元回到 Tensor 单元的直连通路在 PE
    顶层没有接。
19. **描述符的边界只核起点。** 命令处理器只拿一次访问的首行与区域大小比较。地址运算可能
    回绕，缩放因子旁路记录的地址不做检查，对区域表的写入也不校验。
20. **归约单元用不到。** 求最大值与平方和的数据通路都在 Vector 的 RTL 里（平方和已带数值
    修正），但命令处理器没有哪条命令会用到它们。
21. **PE 的对外接口只是占位。** 流口里的网络地址字段没有被使用，流入口的 `last` 标志不做
    检查。本地存储不在控制核的地址空间里。结果只能经 DMA 的搬出命令离开 PE。
22. **操作数不复用。** 每条 Tensor 命令都重新装载全部操作数。从这一版 RTL 数出来的拍数
    包含这部分开销。

### 验证

23. **交接通路在 PE 一级只核到握手。** PE 一级的测试确认了块离开 Tensor 单元并被 Vector
    单元取走。Vector 单元随后写进本地存储的各行，还没有读回来与黄金模型比对。这条通路的各段
    分别在单元级测过数值。PE 一级的交接测试（`test_fastlane_*`）不在 `run_all.py` 的运行
    范围内。
24. **回归测试用的都是行为级存储模型。** 存储封装的 ASAP7 宏分支只有一个封装级的测试
    （`test_l1i_real_a7`）覆盖到，它显示的正是第 14 条里的差别。另有一个测试
    （`test_srambank_real`）单独核宏的 Verilog 模型。没有用同一组激励对比两个分支的测试，
    也没有在宏分支下让 L2 发生争用的测试。
25. **有些断言什么也没查。** 绑在 `pe_top` 上的 99 条断言里，有三条用到的写法被 Verilator
    当成黑盒，实际没有求值。交接 FIFO 的上溢、下溢断言和它的两个粘滞标志，按现在的条件写法
    永远不会触发。
26. **测试运行脚本的几个坑。** 过滤串一个测试也没匹配到时，`run_all.py` 以成功退出。直接
    调 `make` 时，它的退出码看不出 cocotb 测试过没过，要读 `PASS=`/`FAIL=` 那一行。所有
    测试共用一个构建目录，不要同时跑两个。没有装 RISC-V binutils 时，
    `test_rv32_asm_xcheck` 什么也不查就算通过。
27. **缺省情况下查不出漏掉的复位。** Verilator 把所有信号初始化为 0，这也是多数寄存器的
    复位值。加 `XPROP=1` 可以把初值随机化。

### 物理实现

28. **是 EDA 估计，不是硅上的结果。** ASAP7 是预测型 PDK。全部物理结果都是开源流程给出的
    布线后估计。没有做签核，没有对版图做逻辑等价检查，IR 压降、天线规则与时序都没有
    收敛。约束文件里的时钟周期（PE 顶层 12000 ps，两个单元 1670 ps）是流程的设置，不是
    达到的频率。三套版图的时序都没有收敛。最终报告里，Tensor 单元与 Vector 单元这两趟在
    1670 ps 的设置下还有建立时间违例，PE 顶层与 Tensor 单元这两趟还有保持时间违例，三趟都还有
    最大转换时间违例。这些违例既出现在设计内部寄存器到寄存器的路径上，也出现在 I/O 路径上。
    我们不对频率作任何主张。注释里引用的频率数同样不是主张（见
    [注释里的内部引用](#注释里的内部引用)）。
29. **工艺角混用。** 这几趟读的标准单元库是平台缺省的快角，SRAM 宏只有 0.7 V、25 °C 这一
    种特征化条件。由此得到的建立与保持结果不是同一个工作条件下的。
30. **SRAM 宏的各个视图是近似的，彼此也不一致。** 宏来自上游的 `asap7_sram_0p0` 包。它的
    时序库是生成的，漏电与最小周期给的是 0。它的 LEF 与 GDS 在宏的下半部分对不上，所以
    合并后的 GDS 在宏引脚处是否连通没有得到证明；抽查时在那里发现了开路的引脚。在 LEF 里，
    三个控制引脚的接入走线落在宏自己的电源条上。版图把宏的摆放位置挪了 9 nm 来避开由此
    产生的短路，这是绕过去的办法，不是对宏的修正。库里有一个属性打了补丁（见 `patches/`）。
31. **L2 的 bank 用了比需要更宽的宏。** bank 是 32 位宽，映射到 64 位宽的宏上，高半边
    固定为 0，原因是宏包里没有可用的 32 位版图。宏的面积比相匹配的宏所需的要大。
32. **复位释放没有做时序检查，软复位在网表级有已知风险。** PE 只有一个异步复位，经过一个
    两级同步器。在 Tensor 单元的外层封装里，这个复位与命令处理器的软复位合在一起。PE 顶层
    的约束文件对复位端口出发的路径设了伪路径，并屏蔽了全部异步复位脚上的恢复（recovery）
    检查；移除（removal）检查保留。Tensor 单元的约束文件同样对复位端口出发的路径设了伪路径。流程建出的复位网络是一条缓冲器链，不平衡。对更早网表的
    一次分析估计，复位释放在不同区域之间相差一到两个时钟周期，并认为只要复位网络的延迟加上
    偏斜不超过约四拍就可以接受。这个估计出自更早的一版 RTL，当时的运行里包含另一个 PDK。
    偏斜当时没有实测，也没有在这次发布的版图上重新估计。恢复检查被屏蔽之后，时序分析不再
    看守这个余量。同一次分析还查出软复位之后的两处风险。Tensor 单元的异步复位，比交接
    FIFO 的同步清空和 Tensor 单元完成信号上的门控晚一到两拍生效。(a) 在途的块因此可能进入
    已清空的 FIFO，被下一次残差加当作第一个操作数取走，结果被破坏而不报错。(b) 过期的完成
    信号可能穿过门控，使调度器里 Tensor 单元的额度超出上限。这两处在 RTL 仿真里都看不到，
    也都没有在现在的 RTL 与版图上重新分析。那次分析提出了一个固件层面的规避办法，没有测试
    过：软复位连发两次，第二个脉冲至少在第一个之后五拍，两次之间不写门铃。
33. **约束文件里的时序例外是前提，不是结论。** 除第 32 条的复位例外之外，PE 顶层与 Tensor
    单元的约束文件里还有两处。(a) 用 `set_case_analysis` 把 Tensor 单元的数据流选择钉在
    输出驻留模式，只在另一种模式下存在的路径因此不做时序检查。(b) 用
    `set_multicycle_path` 放宽 tile 控制器里一组准静态的控制寄存器（模式、稀疏模式、K 与
    锁存的 tile 描述符），建立四拍、保持三拍。按这些文件里的说明，例外 (b) 依赖 tile
    控制器的装载态与清零态把这些寄存器的锁存与首次使用隔开，并且只对输出驻留模式成立。
    这两个状态一改就要重新推导，而计划中压低每个 tile 固定开销的改动正会改到它们。Tensor
    单元这一趟另有一个钩子脚本，去掉了到输出端口的路径上的建立检查。Vector 单元的约束文件
    没有这些例外。这几趟的时序结果只在这些前提下成立。
